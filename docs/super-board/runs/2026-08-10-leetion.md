## Ordering — why one card per wave

`max_workers: 3` would have dispatched all three Builders into parallel worktrees off the same `main`. The three cards collide pairwise:

| Pair | Shared code |
|---|---|
| #10 ∩ #11 | `updateSpacedRepetition` — both add a new intent to the same function |
| #10 ∩ #12 | the local-calendar-day primitive #12 consumes |
| #11 ∩ #12 | the `buildProperties` property-write guard; must also agree on empty-vs-set popup display |

Serialization is enforced through the **Ready queue**, not a config edit: only one card sits in `Ready` at a time, so the planner cannot fan out. #11 and #12 stay in `Backlog` until their predecessor merges to `main`, so each branch is based on a tree that already contains its dependency. Order: **#10 → #11 → #12**, foundation first.
